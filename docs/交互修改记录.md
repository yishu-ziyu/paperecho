## 第一幕（title 标题 → orbit 轨道 → mirror 镜认）

### T1. title → orbit：卡片"摊开成房间"，替换飞出动画

**现状**

- `src/game/continuum.tsx` 的 `PullCommit`（下拉提交组件）在 `onUp` 里：位移超过 `threshold`（阈值）后执行 `animate(y, threshold * 2.6 * sign, spring.launch)`——卡片向下飞出屏幕，240ms 后 `setTimeout` 调 `onCommit`。
- `src/game/GameShell.tsx` 用 `AnimatePresence mode="sync"`（同步模式，新旧场景同时挂载）+ 0.28s 透明度交叉淡入切换 phase（阶段）。
- `src/game/continuum.tsx` 的 `Craft` 组件带 `layoutId="echo-craft"`（布局形变标识），设计意图是"卡片→桌面→信纸→飞机→回信是同一个物体"，但目前 title 的 Craft 和 orbit 的 Craft 之间没有真正形变——因为卡片先飞走了。
- 后果：手把卡片拉下去 → 卡片消失 → 短暂空窗 → 新场景淡入。"手里的东西"断了，违背 motion.ts 头部注释里自己写的 Continuum rule（连续性原则："the hand never lets go of an object into a button"，手不会把东西交给一个按钮）。

**改成**

下拉标题卡 = 用手把房间"拉开"：

1. 拉动中：卡片跟随手指（现有行为保留）。
2. 松手过阈值：卡片**不飞出**。改为：
   - `PullCommit` 立即触发 `onCommit`（不等 240ms）；
   - 同时把卡片自身的 x/y 用 `spring.settle`（无回弹弹簧，stiffness 280 / damping 34）归零；
   - phase 切换后，`layoutId="echo-craft"` 接管：title 的 `rounded-3xl bg-paper px-6 py-8` 卡片形变为 orbit 的 `inset-[6%] rounded-full bg-paper/70` 圆形纸场。
3. 视觉上：手里的纸"摊大"成了房间的地面。

**实现步骤**

1. `continuum.tsx` · `PullCommit` 新增 prop：
   ```ts
   commitBehavior?: "fly" | "morph";  // 默认 "fly"，不影响其他调用方
   ```
   `onUp` 里分支：
   ```ts
   if (enabledRef.current && dist > threshold) {
     locked.current = true;
     setArmed(false);
     if (commitBehaviorRef.current === "morph") {
       // 不飞出：先切场景，让 layoutId 形变接管；自身位移归零
       commitRef.current();
       void animate(x, 0, spring.settle);
       void animate(y, 0, spring.settle);
     } else {
       const fly = threshold * 2.6 * sign;
       void animate(axis === "y" ? y : x, fly, spring.launch);
       window.setTimeout(() => commitRef.current(), 240);
     }
     return;
   }
   ```
   （`commitBehavior` 和现有 `onCommit` 一样用 ref 持有，避免 effect 重挂。）
2. `TitlePhase.tsx`：标题卡的 `PullCommit` 加 `commitBehavior="morph"`。
3. `GameShell.tsx`：确认 `AnimatePresence mode="sync"` 下两个 phase 同时挂载（现状已是），layoutId 形变才能发生。若形变时旧卡片随退出动画变淡影响观感，给退出态的 `[data-craft]` 单独设 `exit={{ opacity: 1 }}`（让形变清晰可见，不被淡出盖住）。
4. 标题卡内部文字（标题/副标题/"往下拉"）在形变中会显得突兀：包一层 `motion.div`，在 `exit` 时快速淡出文字（0.15s），只留下纸面参与形变。

**验收标准**

- [ ] 下拉松手后，卡片在原位摊大成 orbit 的圆形纸场，全程无飞出、无黑屏空窗。
- [ ] 形变时长约 0.3–0.4s，无跳帧（frame drop）。
- [ ] 信柜卡、orbit 的「你」等其他 `PullCommit` 调用保持原飞出行为（回归测试）。
- [ ] `useReducedMotion`（减弱动效偏好）下退化为点击进入，不受影响。

**风险/注意**

- MotionValue（动画数值）与 layoutId 共存：提交瞬间必须先归零 x/y 再让形变开始，否则形变起点会带着下拉残留位移，出现"跳一下"。
- orbit 的 Craft 是 `pointer-events-none absolute inset-[6%]`，和 title 卡的尺寸差异大，形变时注意 borderRadius 也要参与过渡（motion 的 layoutId 默认处理，若出现硬切，在两个 Craft 上都显式传 `transition={spring.settle}`）。

### T2. 拉动过程反馈：进度显影 + 过阈值的"咔哒"感

**现状**

- `PullCommit` 的提示（如"松开，进房间"）只在 `armed`（已武装，即拉过阈值）为 true 后渲染；拉到一半没有任何进度提示。
- 橡胶阻尼 `rubber()`（拉越远位移越小的阻力函数，上限 `threshold * 1.45`）让后半段位移增量变小，用户容易误判"拉不动了/到头了"。
- `onProgress`（进度回调，0→1）已存在于接口里，`OrbitPhase` 接了（驱动 `gather` 聚拢效果），`TitlePhase` 和信柜都没接。

**改成**

1. **全程进度反馈**：`PullCommit` 内部渲染一个进度提示元素（卡片下方一行字），透明度/位移由进度 t 直接驱动，不需要调用方接 `onProgress`：
   - t = 0 → 完全透明；
   - t → 1 → 渐显为完整文字；
   - 文字内容用 `hint`（如"松开，进房间"）。
2. **过阈值瞬间（armed false→true）**：
   - 文字颜色变为 `text-coral`（珊瑚红，现有 armed 样式保留）；
   - 播 `sfxCharge()`（audio.ts 里已有的蓄力音效：620Hz + 880Hz 两声短音）——**不用新增音效函数**；
   - `navigator.vibrate?.(10)`（手机轻震动 10 毫秒，可选，桌面端自动无效）。
3. 现有"armed 后才显示"的 `<span>` 删除，由上面的进度提示替代。

**实现步骤**

1. `continuum.tsx` · `PullCommit`：
   - 新增内部 state 或 MotionValue：`const progress = useMotionValue(0)`，在 `onMove` 里 `progress.set(t)`；
   - 进度提示元素：
     ```tsx
     <motion.span
       className="pointer-events-none absolute -bottom-6 left-1/2 -translate-x-1/2 whitespace-nowrap text-[0.65rem] tracking-[0.18em]"
       style={{ opacity: progress, color: armed ? "var(--color-coral)" : "var(--color-ink)" }}
     >
       {enabled ? hint : disabledHint}
     </motion.span>
     ```
     （透明度用 MotionValue 驱动，避免 setState 重渲染整个可拖动组件。）
   - armed 跳变检测：用 ref 记录上一次 armed，`onMove` 里 `if (!prevArmed && nextArmed) { sfxCharge(); navigator.vibrate?.(10); }`。disabled 状态下不播音效，只显示 `disabledHint`。
2. `TitlePhase.tsx` / 信柜：不用改（反馈内置在 PullCommit 里），只需确认 `hint` / `disabledHint` 文案合适。
3. `OrbitPhase.tsx`：「你」的 PullCommit 已有 `onProgress={setGather}`，保留；新的内置进度提示会同时出现，确认视觉上不打架（gather 聚拢的是情绪块，进度提示在 blob 下方，位置不同，OK）。

**验收标准**

- [ ] 拉 10% 就能看到提示字开始显影，拉满时完整可读。
- [ ] 过阈值瞬间有音效 + 震动（移动端），且**只在过阈值那一刻播一次**，来回拉动不重复连播。
- [ ] disabled（未满足条件，如还没有情绪靠近时拉「你」）时显示 `disabledHint`，不播音效。
- [ ] 减弱动效偏好下点击提交，流程不受影响。

**风险/注意**

- `sfxCharge` 依赖 AudioContext（音频上下文），浏览器要求用户手势后才能出声——title 的 PullCommit 本身就是手势，没问题；但要确认 `unlockAudio()` 已在首次 pointerdown 调用（目前在 `enter()` 即提交后才解锁，**过阈值音效发生在提交之前，可能无声**——把 `unlockAudio()` 挪到 PullCommit 的 `onPointerDown` 里调一次）。
- 进度提示用 MotionValue 而非 state，避免每帧重渲染 dragging 组件。

### T3. 信柜方向语法统一为"往下"

**现状**

- `TitlePhase.tsx` 信柜：`sign={-1}`（往上拉开信柜），`threshold={42}`。
- 全局语法是"往下 = 带走/提交"（README 玩法里 9 步全部是"往下/拖近"）；return（回信）阶段"再往下，滑进抽屉"也是往下。
- 同一对象"信柜"，开（title）往上、收（return）往下，方向语义矛盾。

**改成**

- 信柜改为 `sign={1}`（往下拉），hint 改为"松开，开信柜"不变，视觉上信柜是底部一个抽屉把手，**往下拽 = 把抽屉拉下来打开**。
- 上方向（sign=-1）从此保留给未来的"送回/归还"类动作，不在第一幕使用。

**实现步骤**

1. `TitlePhase.tsx`：信柜 `PullCommit` 的 `sign={-1}` 改为 `sign={1}`。
2. 视觉微调：信柜元素现在在 `mt-auto mb-8`（底部），往下拉会被拉出屏幕下缘——给外层容器加 `pb-2` 或把 threshold 从 42 降到 36，保证拉到底前能过阈值。
3. 走查 `ArchivePhase.tsx` / `ReturnPhase.tsx` 里所有和信柜/抽屉相关的文案与方向，统一为"往下"（属于第二、三幕走查范围，先记录）。

**验收标准**

- [ ] title 页所有可交互元素只有一个方向：下。
- [ ] 移动端小屏（375×667）下往下拉 36–42px 能稳定触发，不被浏览器下拉刷新/手势冲突（元素已有 `touch-none`，确认即可）。

### O1. orbit：情绪块要有各自的表情表现

**现状**

- `OrbitPhase.tsx` 的 `Token`：每个情绪块是一个 `size-11` 的色块 + `ShapeMark`（形状标记：圆/方/菱形/长条的边框小图标）+ 底部标签文字。
- 情绪差异化只在 `EMOTION_MAP`（emotions.ts）的 `color` / `shape` / `label` / `hint` 上；靠近中心的反馈只有透明度变实 + `box-shadow` 光晕，没有"活"感。
- 8 种情绪：gloom 郁闷（方，蓝灰）、wronged 委屈（圆，红）、anxious 焦虑（菱形，橙）、tired 疲惫（长条，绿）、lonely 孤单（圆，紫）、anger 愤怒（方，砖红）、calm 平静（长条，青）、unseen 想被看见（菱形，金）。

**改成**

情绪块内部加一张"脸"，表情由三个状态量驱动：**closeness**（靠近度 0→1）、**held**（被按住）、**gather**（聚拢进度 0→1）。

| 状态 | 表现 |
|---|---|
| 远处（closeness < 0.42） | 沉睡：眼睛是一条线或闭着，整体半透明（现有 0.55+close*0.45 透明度保留） |
| 靠近（closeness ≥ 0.42） | 睁眼，表情浮现，加现有光晕 |
| held（被按住拖动） | 眼睛睁大，瞳孔看向拖动方向（用拖动增量近似） |
| gather（拉「你」时） | 已靠近的：表情安定（嘴角上扬一点/眼睛柔和）；没靠近的：继续沉睡并变淡（现有 `1 - gather * 0.45` 透明度保留） |

每种情绪的表情性格（落在 `EMOTION_MAP` 新增的 `face` 字段里）：

| 情绪 | 眼睛 | 嘴 | 特殊 |
|---|---|---|---|
| gloom 郁闷 | 下垂眼角 | 一字平嘴 | 靠近时眼角更垂 |
| wronged 委屈 | 圆眼，眼眶略红（浅色内圈） | 下撇嘴 | held 时眼眶红更明显 |
| anxious 焦虑 | 快速眨动（CSS 动画 1.2s 一次） | 波浪形小嘴 | 永远静不下来，沉睡时也慢速眨 |
| tired 疲惫 | 半阖眼（上眼睑盖一半） | 微张的小圆嘴 | gather 时眼睑更垂 |
| lonely 孤单 | 眼睛看向斜下方 | 没有嘴 | 全场唯一没有嘴的 |
| anger 愤怒 | 斜眉压眼 | 咬着的平嘴（双线） | held 时眉毛更斜 |
| calm 平静 | 闭眼弯成弧线 | 浅微笑 | 靠近前后变化最小（它本来就平静） |
| unseen 想被看见 | 睁得最大的眼，瞳孔缓慢左右找 | 小圆嘴 | held 时瞳孔立刻锁定手指方向 |

**实现步骤**

1. `emotions.ts` · `Emotion` 类型加字段：
   ```ts
   face: {
     eyes: "closed" | "half" | "downcast" | "round" | "wide" | "side" | "brow";
     mouth: "flat" | "frown" | "wave" | "open" | "none" | "smile" | "bite";
     blink?: boolean;  // anxious 专用
   };
   ```
   按上表给 8 种情绪填 `face`。
2. 新建 `src/game/components/TokenFace.tsx`：SVG 小组件，props 为 `face`、`awake: boolean`（closeness ≥ 0.42）、`held: boolean`、`gaze: {x, y} | null`（视线方向）。尺寸适配 `size-11`（44px）网格内部。
3. `OrbitPhase.tsx` · `Token`：
   - 替换/补充 `ShapeMark`：色块内嵌 `<TokenFace>`；
   - held 时把拖动增量（`useDrag` 的 `movement` 或 `delta`）传给 `gaze`；
   - anxious 的眨动用 CSS `@keyframes` + `transform: scaleY()` 做眼睑，**不用滤镜**。
4. 形状保留（形状是情绪的外轮廓识别，脸是性格）：方形/菱形色块里脸照常画。

**验收标准**

- [ ] 8 种情绪两两可区分：遮住标签文字，只看脸能认出至少 6 种。
- [ ] 拖一个远处情绪靠近中心：能观察到"沉睡 → 睁眼"的变化（阈值 0.42 处切换，可加 0.2s 过渡）。
- [ ] held 时眼睛跟手；松手回到原位表情随之恢复。
- [ ] 拉「你」gather 时，靠近的 2–3 个块表情变化可感知。
- [ ] 移动端 Safari + Chrome 各拖一遍无掉帧（只用 transform/opacity）。

**风险/注意**

- SVG 表情别画太细：44px 里能看清的元素不超过 3 个（两眼一嘴）。
- `token-float`（现有漂浮动画）和眨动动画叠加时注意 `transform` 冲突——漂浮在外层、眨动在内层元素。

### O2. orbit → mirror：认领的情绪跟随到下一幕

**现状**

- `commitOrbit()`（store.ts）算出 `fingerprint`（情绪指纹）→ `matchStories(feels, 3, avoid)` 匹配 3 个候选故事 → 切到 mirror。
- `MirrorPhase.tsx` 只渲染 3 张候选卡（城市 · 名字 + opening 开场白），玩家聚拢的情绪块完全消失，"因为你有这些情绪，所以见到这些话"的因果关系不可见。

**改成**

1. **跟随**：进入 mirror 时，已认领的情绪（`ownedOf(fingerprint, 0.42)` 的结果）以缩小形态（28px 小印记，带 O1 的表情）落在 Guide 下方一行，像是"你口袋里带进来的东西"。
2. **因果染色**：每张候选卡角落显示它与你哪个情绪共鸣（小色点 + 情绪名）。实现上需要 `matchStories` 返回每个候选的匹配来源（见实现步骤 2）；若暂不想改 matching 逻辑，备选方案：卡片用你 top-1 情绪的颜色做左边框染色 + 一句"因为{郁闷}，你听见这句"。

**实现步骤**

1. `MirrorPhase.tsx`：Guide 下加一行：
   ```tsx
   const owned = ownedOf(useGame((s) => s.fingerprint), 0.42);
   // 渲染为 28px 小印记横排，复用 O1 的 TokenFace（awake 状态）
   ```
   入场动画：从上方落下的 spring（`spring.settle`），象征"从上一幕带进来"。
2. 因果染色（完整版）：`stories.ts` 的 `matchStories` 目前只返回 3 个 story。改为返回 `{ story, matchedBy: EmotionId }[]`，`store.commitOrbit` 存下 `matchedBy`，`MirrorPhase` 在卡片左上角渲染对应情绪的小印记。
3. 文案配合：Guide body 改为"这些是你带来的。往下拖一句到桌上——认领，不是点选。"

**验收标准**

- [ ] orbit 里认领了几个情绪，mirror 顶部就出现几个小印记，数量、种类一致。
- [ ] 每张候选卡能看出"它和哪个情绪共鸣"。
- [ ] goBack 从 mirror 回 orbit 再进来，印记不丢失（fingerprint 在 store 里，天然保留，确认即可）。

**风险/注意**

- `matchStories` 改动会影响 store 和可能的测试，先看 `stories.ts` 里现有调用方再动手；备选方案（top-1 染色）零侵入，可先上。

### O3. orbit 底部状态栏与 Guide 文案去重

**现状**（OrbitPhase.tsx）

- Guide：`title="把靠近你的留下"` `body="拖近中心，就是你。把「你」往下带，才算带走。"`——指令。
- 底部 `<p>`：`held && heldClose >= 0.42` 时显示 `EMOTION_MAP[held].hint`；`owned.length` 时显示"{xx、xx} 靠近了。把「你」往下拉。"；否则显示"先把一块拖近自己"——指令和反馈混在一起，"把「你」往下拉"与 Guide 的"把「你」往下带"重复。

**改成**

- 指令只留 Guide 一处。
- 底部只保留**情境反馈**：
  - held 且已靠近：`EMOTION_MAP[held].hint`（如"胸口像压着一层湿空气"）——情绪的低语，保留；
  - owned.length > 0：只报状态"{郁闷、疲惫} 靠近了"，删掉"把「你」往下拉"；
  - 什么都没有：留空（现有 `min-h-5` 已防布局跳动，直接置空即可）。

**实现步骤**

1. `OrbitPhase.tsx` 底部 `<p>` 的三元表达式改为：
   ```tsx
   {held && heldClose >= 0.42
     ? EMOTION_MAP[held].hint
     : owned.length
       ? `${owned.map((f) => EMOTION_MAP[f.id].label).join("、")} 靠近了`
       : ""}
   ```
2. Guide 文案保持不动（它已是唯一指令源）。

**验收标准**

- [ ] 全幕任意状态下，"下一步该做什么"只有 Guide 在说；底部只说"现在是什么状态"。
- [ ] 三种状态切换时底部高度不跳动。
