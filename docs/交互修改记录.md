## 第一幕（title 标题 → orbit 轨道 → mirror 镜认）

### T1. title → orbit：卡片"摊开成房间"，替换飞出动画

- **现状**：`PullCommit`（下拉提交组件）提交时把卡片向下飞出屏幕（`fly = threshold * 2.6`，阈值的 2.6 倍距离），240ms 后切换 phase（阶段），新场景靠 0.28s 淡入。手里的东西消失了，再出现一个新场景——违背 continuum.tsx 里自己写的设计原则（"手和物之间不能出现空洞"）。
- **改成**：下拉过程中卡片随手势逐渐展开；松手过阈值后，卡片通过 `layoutId`（布局形变标识，让两个元素之间做形变过渡）从 `rounded-3xl`（大圆角卡片）形变为 orbit 场景的圆形纸场——**拉开的动作就是房间打开的动作**。
- **技术要点**：
  - `PullCommit` 需要增加一种提交模式："形变提交"（不飞出，提交时把位移平滑交给 layoutId 形变）。
  - 注意 MotionValue（动画数值）与 layoutId 共存：提交瞬间先把卡片的 x/y 动画归零（或让形变起点视觉重合），避免跳帧。
  - 信柜卡片的提交仍保留原方式或同样评估。
- **状态**：✅ 已接受，待实现

### T2. armed（已武装/过阈值）提示太晚，增加过程反馈

- **现状**：提示文字（"松开，进房间"）只在拉过阈值后才出现；橡胶阻尼（rubber band，拉越远位移越小的阻力效果）让后半段手感"拉不动"，用户不知道还差多少。
- **改成**：
  - 拉动全程给进度反馈：卡片下缘一行字随进度 t（0→1）渐显。
  - 过阈值瞬间：文字变色 + 轻音效 + `navigator.vibrate(10)`（手机轻震动 10 毫秒）。
  - `onProgress`（进度回调）接口已在 continuum.tsx 里存在，title 和信柜目前没接，接上即可。
- **状态**：✅ 已接受，待实现

### T3. 信柜方向语法统一为"往下"

- **现状**：全局语法是"往下 = 带走/提交"，但 title 页信柜是 `sign={-1}`（往上拉），而 return（回信）阶段又是"再往下，滑进抽屉"。同一对象方向矛盾。
- **改成**：信柜改为往下拉（抽屉从底部被"拽下来"）。上方向保留给未来"送回/归还"类动作。
- **状态**：✅ 已接受，待实现

### O1. orbit：情绪块要有各自的表情表现

- **现状**：情绪块（token）只有形状（圆/方/菱形/长条）+ 颜色 + 标签文字区分，靠近中心只是透明度变实、加一圈光晕，没有"活"的表情。
- **改成**：每个情绪块根据 closeness（靠近度，0→1）呈现不同的表情/状态变化，例如：
  - 远处：表情模糊、沉睡或背对你（半透明 + 简化五官）。
  - 靠近：睁开眼睛、表情浮现，且**每种情绪的表情性格不同**（如"倦"是半阖眼，"躁"是快速眨动，"空"是没有嘴）。
  - 被拖动（held）时：表情看向手指方向或睁大。
  - 拉「你」gather（聚拢）时：靠近的块表情变得安定/期待，没靠近的继续沉睡。
- **实现方向**：情绪块内部从纯 CSS 形状改为小组件（SVG 或分层 div），表情状态由 closeness + held + gather 三个值驱动；`EMOTION_MAP`（情绪映射表）里为每种情绪加表情定义。
- **注意**：保持移动端性能，表情动画用 transform/opacity，不用滤镜。
- **状态**：✅ 已接受，待实现

### O2. orbit → mirror：认领的情绪要跟随到下一幕

- **现状**：orbit 里辛苦聚拢的情绪块，提交后散落状态被丢弃，mirror（镜认阶段）里只剩三张陌生卡片，"这些是我的"的体感断了。
- **改成**：进入 mirror 时，认领的情绪以缩小形态跟随（候选卡旁的小印记），或让候选卡显示"因为你有这些情绪，所以见到这些话"的染色关联（candidates 候选本来就是按 `matchStories(feels)` 情绪匹配出来的，视觉上要把这层因果露出来）。
- **状态**：✅ 已接受，待实现

### O3. orbit 底部状态栏与 Guide（引导文案）职责重叠

- **现状**：Guide 说"拖近中心，就是你"，底部状态栏又说"先把一块拖近自己"，两处文案重复，玩家不知道看哪。
- **改成**：底部只保留情境反馈（held 按住时的 hint 提示、已靠近情绪的列表）；"下一步指令"统一收进 Guide 一处。
- **状态**：✅ 已接受，待实现
